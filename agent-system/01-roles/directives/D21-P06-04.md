# Directive — D21 for P06-04

## Goal

Build minimal swap and liquidity-support panels that let a judge generate on-chain activity from the frontend. These interactions should drive hook scoring and make the leaderboard update.

Use the already deployed `V4PoolActionHelper` from the P05-03 manifests wherever feasible. Do not deploy new contracts in this phase unless absolutely blocked.

## Scope (In)

### 1. ABIs

Add or extend frontend ABIs for:

```text
frontend/lib/abis/erc20-faucet.ts
frontend/lib/abis/v4-pool-action-helper.ts
```

ERC20 ABI must include:

```solidity
function allowance(address owner, address spender) external view returns (uint256)
function approve(address spender, uint256 amount) external returns (bool)
function balanceOf(address owner) external view returns (uint256)
function decimals() external view returns (uint8)
```

Helper ABI must include:

```solidity
function swap(address payer, PoolKey key, SwapParams params, bytes hookData) external returns (BalanceDelta delta)
function modifyLiquidity(address payer, PoolKey key, ModifyLiquidityParams params, bytes hookData) external returns (BalanceDelta delta)
```

Use ABI tuple shapes compatible with `V4PoolActionHelper.sol`:

- `PoolKey`: `(address currency0, address currency1, uint24 fee, int24 tickSpacing, address hooks)`
- `SwapParams`: `(bool zeroForOne, int256 amountSpecified, uint160 sqrtPriceLimitX96)`
- `ModifyLiquidityParams`: `(int24 tickLower, int24 tickUpper, int256 liquidityDelta, bytes32 salt)`

### 2. Pool helpers

Add frontend utilities, for example:

```text
frontend/lib/pools.ts
```

Responsibilities:

- Build a pool key from the selected team deployment data:
  - `currency0`
  - `currency1`
  - `fee = 8388608`
  - `tickSpacing = 60`
  - `hooks = deployments.core.hook`
- Determine swap direction:
  - xUSD to team token: `zeroForOne = currency0 === xUSD`
  - team token to xUSD: `zeroForOne = currency0 === team token`
- Export safe constants for v4 price limits:
  - for zeroForOne use `4295128740`
  - for oneForZero use `1461446703485210103287273052203988822378723970341`
- Export full-range ticks for `tickSpacing = 60` if adding liquidity through helper:
  - `tickLower = -887220`
  - `tickUpper = 887220`

### 3. SwapPanel

Add:

```text
frontend/components/SwapPanel.tsx
```

Requirements:

- Team selector for BRA/ARG/FRA/GER.
- Direction toggle:
  - xUSD → TEAM
  - TEAM → xUSD
- Amount input.
- Read selected input token balance and allowance to `deployments.core.liquiditySeeder`.
- Two-step transaction flow:
  1. Approve helper if allowance is insufficient.
  2. Call helper `swap(payer, key, params, hookData)`.
- `payer = connected wallet address`.
- `hookData` should encode the connected wallet address as 20 raw bytes so hook scoring resolves the user correctly. If viem ABI encoding makes raw 20-byte hookData difficult, document the chosen method and verify it matches the local helper/smoke path.
- Use exact-input swaps by setting `amountSpecified` negative for the input amount.
- Show active fee preview using current match state/fee data already available in the frontend or a small read path. Clear units are enough: bps and percent.
- On receipt success, refetch allowance/balance if present. Leaderboard already polls every 5 seconds, so no global state wiring is required.
- Disable when disconnected, wrong chain, invalid amount, approving, or swapping.
- Show simple status text: approve pending/confirmed, swap pending/confirmed/error.

### 4. LiquidityPanel

Add:

```text
frontend/components/LiquidityPanel.tsx
```

Requirements:

- Team selector.
- Amount input labelled xUSD side amount.
- For MVP, compute a matching team-token amount equal to the xUSD amount because pools were initialized at 1:1 and seeded full-range.
- Read xUSD and selected team-token allowances to helper.
- Two/three-step transaction flow:
  1. Approve xUSD if insufficient.
  2. Approve team token if insufficient.
  3. Call helper `modifyLiquidity(payer, key, params, hookData)`.
- `liquidityDelta` can be a simple deterministic value derived from the input amount. If exact full-range math is too expensive, use `liquidityDelta = parsedAmount` and clearly label the panel as demo liquidity support.
- Use full-range ticks from `frontend/lib/pools.ts`.
- `salt` can be a fixed bytes32 value derived from the wallet/team or zero bytes if the helper accepts it.
- On success, leaderboard should update through its existing polling.
- If the helper call reverts during validation due to v4 liquidity math or token settlement, keep SwapPanel complete and mark LiquidityPanel as `PARTIAL` with a precise reason. Do not spend the whole phase reinventing v4 math.
