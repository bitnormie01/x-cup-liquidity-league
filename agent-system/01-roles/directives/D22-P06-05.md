# Directive — D22 for P06-05

## Goal

Complete the frontend demo with three final panels:

1. Match-state simulator for the controller wallet.
2. Live event log for hook/registry events.
3. Contract proof panel with deployed addresses and explorer links.

This phase should make the judge demo self-contained after connecting a wallet.

## Scope (In)

### 1. Registry ABI extension

Extend `frontend/lib/abis/xcup-registry.ts` with:

```solidity
function controller() external view returns (address)
function owner() external view returns (address)
function setMatchState(bytes32 teamId, uint8 state, string reason) external

event MatchStateUpdated(bytes32 indexed teamId, uint8 state, string reason, uint64 updatedAt)
```

Keep existing `matchStateOfTeam` support.

### 2. Hook event ABI extension

Extend `frontend/lib/abis/xcup-hook.ts` with event ABI entries for:

```solidity
event DynamicFeeApplied(
  bytes32 indexed poolId,
  bytes32 indexed teamId,
  address indexed user,
  uint8 state,
  uint24 baseFeeBps,
  uint24 discountBps,
  uint24 penaltyBps,
  uint24 finalFeeBps
)

event TeamPointsAwarded(
  bytes32 indexed poolId,
  bytes32 indexed teamId,
  address indexed user,
  uint8 source,
  uint256 rawAmount,
  uint256 multiplierBps,
  uint256 points
)

event WashPenaltyApplied(
  bytes32 indexed poolId,
  bytes32 indexed teamId,
  address indexed user,
  uint8 reason,
  uint24 feePenaltyBps,
  uint256 timestamp
)
```

Use ABI shapes compatible with the Solidity event definitions. If viem requires enum fields as `uint8`, use `uint8`.

### 3. MatchStateSimulator

Add:

```text
frontend/components/MatchStateSimulator.tsx
```

Requirements:

- Visible only when URL has `?admin=1` OR when `NODE_ENV !== 'production'`.
- Team selector using existing `TeamSelector`.
- Six buttons for enum values 0 through 5 using labels from `match-states.ts`.
- Optional reason text input defaulting to `demo`.
- Read `registry.controller()` and `registry.owner()`.
- If connected wallet is neither controller nor owner, show `Connect as controller/owner to use this panel` and disable writes.
- Call `registry.setMatchState(teamId, state, reason)` via `useWriteContract`.
- Use `useWaitForTransactionReceipt` and status text.
- Disable buttons while tx pending/confirming.
- Add a light anti-spam cooldown: after a successful write, disable buttons for about 3 seconds.

### 4. EventLog

Add:

```text
frontend/components/EventLog.tsx
```

Preferred approach:

- Use `useWatchContractEvent` if it works cleanly for hook/registry events.
- If public RPC/event subscription is unreliable, use polling with viem public client `getLogs` every 5 seconds.

Requirements:

- Display last 20 events in memory.
- Include event name, team symbol if resolvable, user if relevant, key numeric fields, and tx explorer link.
- Events to capture:
  - Hook `DynamicFeeApplied`
  - Hook `TeamPointsAwarded`
  - Hook `WashPenaltyApplied`
  - Registry `MatchStateUpdated`
- Add loading/empty/error states.
- It is acceptable to only show events observed after page load if implementing watch-based event capture.
- If using polling, bound the queried block range to avoid heavy RPC calls. A simple last-2000-block rolling window is fine.

### 5. ContractProofPanel

Add:

```text
frontend/components/ContractProofPanel.tsx
```

Requirements:

- Show chain ID and network name.
- Show explorer links for:
  - xUSD
  - BRA, ARG, FRA, GER
  - PoolManager
  - XCupLeagueRegistry
  - TeamPassport
  - XCupLiquidityLeagueHook
  - LiquiditySeeder helper
- Show pool IDs for all four teams.
- Disclose project-owned PoolManager clearly.

### 6. Page integration

Update `frontend/app/page.tsx`:

- Add `MatchStateSimulator`, `EventLog`, and `ContractProofPanel` below swap/liquidity panels.
- Remove the P06-05 placeholder.
- Preserve all existing panels.
