# Directive — D13 for P05-02

## Context

P05-01 is accepted. The repo now has deterministic scripts for token deployment and core deployment. `DeployTokens.s.sol` writes `deployments/<chainId>/tokens.json`; `DeployCore.s.sol` writes `deployments/<chainId>/core.json`, deploys/uses `PoolManager`, deploys the hook with correct v4 flag bits, and registers the four teams.

This phase must turn those deployed contracts into usable Uniswap v4 pools for the demo path.

## Goal

Create the four dynamic-fee Uniswap v4 pools (`BRA/xUSD`, `ARG/xUSD`, `FRA/xUSD`, `GER/xUSD`) with the X Cup hook attached, register each pool in `XCupLeagueRegistry`, seed enough local liquidity for basic demo swaps, and write structured deployment manifests for downstream testnet deployment and frontend consumption.

## Scope (In)

### 1. `contracts/script/CreatePools.s.sol`

Implement a Foundry script that:

- Reads `deployments/<chainId>/tokens.json` and `deployments/<chainId>/core.json`.
- Parses:
  - quote token address (`xUSD`)
  - four fan token addresses and symbols
  - registry address
  - poolManager address
  - hook address
- For each fan token, builds a sorted Uniswap v4 `PoolKey`:
  ```solidity
  PoolKey memory key = PoolKey({
      currency0: Currency.wrap(token0),
      currency1: Currency.wrap(token1),
      fee: LPFeeLibrary.DYNAMIC_FEE_FLAG,
      tickSpacing: 60,
      hooks: IHooks(hook)
  });
  ```
- Sorts currencies by raw address value before constructing `PoolKey`. Do not assume quote token is always `currency0` or `currency1`.
- Initializes each pool at 1:1 using:
  ```solidity
  uint160 constant SQRT_PRICE_1_1 = 79228162514264337593543950336;
  poolManager.initialize(key, SQRT_PRICE_1_1);
  ```
  If the installed v4 API requires a third hookData argument, use the installed signature and document it in the report.
- Calls:
  ```solidity
  registry.registerPool(key.toId(), teamId, Currency.wrap(fanToken), Currency.wrap(quoteToken));
  ```
  Use `teamId = keccak256(bytes(symbol))`, matching `DeployCore.s.sol`.
- Writes `deployments/<chainId>/pools.json` with at least:
  - `chainId`
  - `poolManager`
  - `registry`
  - `hook`
  - `fee`
  - `tickSpacing`
  - for each team: `symbol`, `teamId`, `poolId`, `fanToken`, `quoteToken`, `currency0`, `currency1`

### 2. `contracts/script/SeedLiquidity.s.sol`

Implement a Foundry script that:

- Reads `tokens.json`, `core.json`, and `pools.json`.
- Mints enough `xUSD` and fan tokens to the deployer using the owner-only `mint` functions. Since the deployer is the owner from P05-01 scripts, this is acceptable for local/testnet demo seeding.
- Adds a small, deterministic full-range or near-full-range liquidity position for each pool.
- Prefer using available v4 periphery contracts if they already exist in `contracts/lib/v4-periphery` and can be used without adding dependencies.
- If periphery is too heavy, implement a minimal local script helper using `PoolManager.unlock` and `modifyLiquidity`, following the installed v4-core lock/unlock settlement pattern.
- Do not change production contracts to make seeding easier.
- Writes `deployments/<chainId>/seed.json` with at least:
  - `chainId`
  - `liquiditySeeder` or helper address if deployed
  - per team: `symbol`, `poolId`, `liquidityDelta`, `fanTokenAmount`, `quoteTokenAmount`

### 3. Local anvil end-to-end validation

Run from `contracts/` against a fresh local anvil:

```bash
forge script script/DeployTokens.s.sol --rpc-url http://127.0.0.1:8545 --broadcast --private-key <anvil-key>
forge script script/DeployCore.s.sol --rpc-url http://127.0.0.1:8545 --broadcast --private-key <anvil-key>
forge script script/CreatePools.s.sol --rpc-url http://127.0.0.1:8545 --broadcast --private-key <anvil-key>
forge script script/SeedLiquidity.s.sol --rpc-url http://127.0.0.1:8545 --broadcast --private-key <anvil-key>
```

Then verify:

- `deployments/31337/pools.json` exists locally.
- `deployments/31337/seed.json` exists locally.
- `registry.isRegisteredPool(poolId)` returns true for all four pool IDs.
- At least one basic swap path succeeds after liquidity seeding. If a full swap helper is too expensive for the phase, report `PARTIAL` only if pools/registry/liquidity work but swap sanity remains unproven.
