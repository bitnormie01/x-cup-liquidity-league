# Directive — D19 for P06-03

## Goal

Build the live leaderboard and per-team cards. This should become the visual centerpiece of the demo: judges can see team rankings, points, fans, match state, active fee, and pool links from live X Layer testnet contract reads.

## Scope (In)

### 1. ABIs

Add or extend minimal frontend ABIs under `frontend/lib/abis/`.

Hook ABI must support:

```solidity
function getTeamScore(bytes32 teamId) external view returns (uint256 swapPoints, uint256 lpPoints, uint256 totalPoints, uint64 lastUpdatedAt)
function feeForState(uint8 state) external view returns (uint24)
```

Registry ABI must support:

```solidity
function matchStateOfTeam(bytes32 teamId) external view returns (uint8 state, string reason, uint64 updatedAt, bool exists)
```

TeamPassport ABI already supports:

```solidity
function teamFanCount(bytes32 teamId) external view returns (uint256)
```

If the current ABI files already contain some of this, extend them rather than duplicating.

### 2. Match-state helpers

Add:

```text
frontend/lib/match-states.ts
```

Export labels and UI metadata for enum values:

```text
0 PRE_MATCH
1 LIVE_NORMAL
2 GOAL_SHOCK
3 RED_CARD
4 PENALTY
5 FINAL_WHISTLE
```

Include:

- label
- short label
- color/className metadata
- fallback for unknown state

### 3. Leaderboard data hook

Create a small hook or utility, for example:

```text
frontend/lib/use-league-data.ts
```

or keep it in `components/Leaderboard.tsx` if simpler.

It must use wagmi reads to fetch for all four teams:

- Hook `getTeamScore(teamId)`
- Registry `matchStateOfTeam(teamId)`
- Hook `feeForState(state)` after state is known, or read all six fees and map client-side
- TeamPassport `teamFanCount(teamId)`

Preferred implementation under time pressure:

- One `useReadContracts` call for scores, match states, and fan counts.
- One `useReadContracts` call for all six `feeForState` values.
- Poll every 5 seconds through query `refetchInterval: 5000`.
- If `useBlockNumber({ watch: true })` is easy, refetch on block changes. If it creates noisy code, document that 5-second polling is used instead.

### 4. Leaderboard component

Add:

```text
frontend/components/Leaderboard.tsx
```

Requirements:

- Render 4 rows.
- Columns:
  - Rank
  - Team: flag + name + symbol
  - Total Points
  - Swap Points
  - LP Points
  - Fans
  - Match State
  - Active Fee
  - Pool / Explorer link
- Sort descending by:
  1. totalPoints
  2. lpPoints
  3. fanCount
  4. symbol ascending as final deterministic tie-breaker
- Include loading, empty, and error states.
- Format points as readable integers or short decimals; points are integer-like in current hook scoring, so avoid misleading token-style decimals if values are already whole points.
- Explorer pool link may use the poolId as display and OKX explorer base; if there is no direct pool URL format, link to the hook or registry address and label clearly. Do not invent a broken pool URL.

### 5. TeamCard component

Add:

```text
frontend/components/TeamCard.tsx
```

Requirements:

- Show flag, name, symbol.
- Show total/swap/LP points.
- Show fan count.
- Show match-state label with color coding.
- Show active fee as percent or bps; make units clear.
- Show pool ID truncated.
- Show explorer link to the team token or registry/hook; do not invent unsupported pool page URL.

### 6. Page integration

Update `frontend/app/page.tsx`:

- Add leaderboard above team cards.
- Add team cards grid below leaderboard.
- Preserve header, wallet/network controls, deployment status, faucet/passport panels.
- Remove or replace the P06-03 placeholder.
- Keep P06-04 placeholder for swap/liquidity.
