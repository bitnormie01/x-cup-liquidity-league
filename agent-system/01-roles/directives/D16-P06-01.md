# Directive — D16 for P06-01

## Goal

Bootstrap the frontend under `frontend/` with a minimal Next.js + TypeScript + Tailwind + wagmi/viem app that connects a wallet, detects X Layer testnet, and loads the committed P05-03 deployment manifests. This phase only creates the shell and wallet/network foundation for the judge demo.

## Scope (In)

### 1. Create frontend app

Create a `frontend/` project with:

```text
frontend/
  app/
    layout.tsx
    page.tsx
    globals.css
  components/
    WalletButton.tsx
    NetworkBadge.tsx
  lib/
    chains.ts
    wagmi-config.ts
    deployments.ts
  public/
  package.json
  tsconfig.json
  next.config.mjs
  tailwind.config.ts
  postcss.config.mjs
  .env.example
```

Use Next.js App Router, TypeScript, and Tailwind.

### 2. Wallet stack

Use the lightest reliable path under time pressure:

- Prefer `wagmi` + `viem` + injected connector.
- RainbowKit is optional, not required.
- Avoid dependency bloat if install/build becomes slow.

`WalletButton.tsx` must:

- show a connect button when disconnected
- show shortened wallet address when connected
- offer disconnect
- avoid throwing if no injected wallet is present

### 3. X Layer testnet chain config

`frontend/lib/chains.ts` must export X Layer testnet:

```ts
id: 1952
name: 'X Layer Testnet'
nativeCurrency: { name: 'OKB', symbol: 'OKB', decimals: 18 }
rpc: https://testrpc.xlayer.tech/terigon
explorer: https://www.okx.com/web3/explorer/xlayer-test
```

`frontend/lib/wagmi-config.ts` must configure wagmi/viem for this chain.

### 4. Deployment manifest loading

`frontend/lib/deployments.ts` must expose typed frontend deployment data from the committed P05-03 manifests.

Preferred approach for reliability:

- Copy or import from `../deployments/xlayer-testnet/*.json` only if Next/TS build supports it cleanly.
- If importing JSON outside frontend root becomes painful, create a simple TypeScript constant file manually using the committed manifest values.

Must export at least:

- `chainId`
- token addresses: xUSD, BRA, ARG, FRA, GER
- core addresses: PoolManager, Registry, TeamPassport, Hook, LiquiditySeeder helper
- pool IDs for all four teams
- `poolManagerMode`

### 5. UI shell

`app/page.tsx` must render:

- product title: `X Cup Liquidity League`
- subtitle: `World Cup fan battles powered by Uniswap v4 Hooks on X Layer`
- wallet button
- network badge
- visible deployment status card showing:
  - chain ID 1952
  - registry address
  - hook address
  - project-owned PoolManager disclosure
- three placeholder panels for later phases:
  - Faucet + Passport
  - Leaderboard + Team Cards
  - Swap + Liquidity Support

Keep it clean and judge-friendly. No fancy animation, no chart libraries.

### 6. Network badge

`NetworkBadge.tsx` must:

- show connected chain status
- show correct state when connected to X Layer testnet
- show wrong-network state otherwise
- provide a switch-network CTA if wagmi supports it
- fail gracefully if wallet does not support programmatic switch

### 7. Local validation and report

Run from `frontend/`:

```bash
pnpm install
pnpm build
```

If practical, also run `pnpm dev` and verify the page loads locally. Capture a screenshot to:

```text
agent-system/04-summaries/screenshots/P06-01.png
```

If screenshot capture is not available in the Executor environment, document that in the report; do not block if `pnpm build` passes.

## Scope (Out)

- No contract reads beyond static manifest display. Live reads start P06-03.
- No faucet/passport transactions. That is P06-02.
- No leaderboard implementation. That is P06-03.
- No swap/liquidity UI. That is P06-04.
- No match-state admin UI or event log. That is P06-05.
- No backend, API routes, database, subgraph, or indexer.
- No mainnet support.
