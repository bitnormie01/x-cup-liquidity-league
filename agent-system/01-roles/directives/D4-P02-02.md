# Directive — D4 for P02-02

## Goal

Implement `contracts/src/TeamPassport.sol`: a soulbound (non-transferable) ERC-721 where each wallet can mint exactly one passport that locks in a `bytes32 teamId`. The Hook (P04) will read `teamOf` / `isSupporter` to apply loyalty multipliers and supporter discounts. No tests yet, no registry coupling, no metadata URI work — those land in later phases.

## Scope (In)

- Create `contracts/src/TeamPassport.sol`:
  - SPDX `MIT`, `pragma solidity 0.8.26;`.
  - Imports (use exactly these — they go through the existing remappings):
    - `import {ERC721} from "@openzeppelin/contracts/token/ERC721/ERC721.sol";`
    - `import {Ownable} from "@openzeppelin/contracts/access/Ownable.sol";`
  - `contract TeamPassport is ERC721, Ownable`.
  - Constructor signature: `constructor(address owner_) ERC721("X Cup Team Passport", "XCUP-PASS") Ownable(owner_)`. Do not pre-mint anything.
  - Storage (declare exactly these names, types, and order):
    ```solidity
    struct PassportData {
        bytes32 teamId;
        uint64 mintedAt;
        bool exists;
    }

    mapping(address => PassportData) public passportOf;
    mapping(bytes32 => uint256) public teamFanCount;
    mapping(address => uint256) public tokenIdOf;
    uint256 public nextTokenId;
    ```
  - Custom errors (declare exactly these — do NOT use `require(..., "string")`):
    - `error Soulbound();`
    - `error AlreadyMinted();`
    - `error InvalidTeam();`
  - Event:
    ```solidity
    event PassportMinted(address indexed fan, uint256 indexed tokenId, bytes32 indexed teamId);
    ```
  - Functions:
    - `function mintPassport(bytes32 teamId) external returns (uint256 tokenId)` that:
      - reverts with `InvalidTeam()` if `teamId == bytes32(0)`.
      - reverts with `AlreadyMinted()` if `passportOf[msg.sender].exists` is true.
      - assigns `tokenId = nextTokenId;` then `unchecked { nextTokenId = tokenId + 1; }` (the counter cannot realistically overflow in MVP and the `unchecked` saves a touch of gas — fine to leave plain `nextTokenId++` if you find that more readable, but do NOT add SafeMath / Math.tryAdd).
      - writes `passportOf[msg.sender] = PassportData({ teamId: teamId, mintedAt: uint64(block.timestamp), exists: true });` BEFORE calling `_safeMint` (checks-effects-interactions).
      - writes `tokenIdOf[msg.sender] = tokenId;`.
      - writes `teamFanCount[teamId] += 1;`.
      - calls `_safeMint(msg.sender, tokenId);`.
      - emits `PassportMinted(msg.sender, tokenId, teamId);`.
      - returns `tokenId`.
    - `function teamOf(address fan) external view returns (bytes32)` — returns `passportOf[fan].teamId` (this naturally returns `bytes32(0)` when no passport exists).
    - `function hasPassport(address fan) external view returns (bool)` — returns `passportOf[fan].exists`.
    - `function isSupporter(address fan, bytes32 teamId) external view returns (bool)` — returns `passportOf[fan].exists && passportOf[fan].teamId == teamId`.
  - Soulbound enforcement via OZ v5 `_update` hook:
    ```solidity
    function _update(address to, uint256 tokenId, address auth)
        internal
        override
        returns (address)
    {
        address from = _ownerOf(tokenId);
        if (from != address(0) && to != address(0)) {
            revert Soulbound();
        }
        return super._update(to, tokenId, auth);
    }
    ```
    - This MUST permit mints (`from == address(0)`) and reject every transfer/approval-driven move where both sides are non-zero. Do NOT also block burns (`to == address(0)`); we do not expose a burn path in this phase, but leaving burns technically permitted is fine and matches the plan.
  - NatSpec: one-line `@notice` on the constructor, `mintPassport`, `teamOf`, `hasPassport`, `isSupporter`, and `_update`. No `@dev` paragraphs.
  - Do NOT override `tokenURI`, `supportsInterface`, `name`, `symbol`, or `decimals`.
- Run `cd contracts && forge build` and `cd contracts && forge fmt --check`. Both MUST pass cleanly. Paste verbatim output into the report Tests table.
