# Directive — D17 for P06-02

## Goal

Add the first interactive frontend demo flows: faucet claims for xUSD and all four fan tokens, plus TeamPassport minting and passport-state display. This phase should let a judge connect a wallet, get demo tokens, choose a team, mint a soulbound passport, and see initial user contribution numbers.

## Scope (In)

### 1. ABIs

Create minimal hand-written ABIs under:

```text
frontend/lib/abis/
  demoToken.ts
  teamPassport.ts
  xCupLiquidityLeagueHook.ts
```

Required token ABI functions:

- `balanceOf(address) view returns (uint256)`
- `FAUCET_AMOUNT() view returns (uint256)`
- `FAUCET_COOLDOWN() view returns (uint256)`
- `lastFaucetAt(address) view returns (uint256)`
- `faucetMint(address)`
- `symbol() view returns (string)`
- `decimals() view returns (uint8)`

Required TeamPassport ABI functions:

- `mintPassport(bytes32) returns (uint256)`
- `hasPassport(address) view returns (bool)`
- `passportOf(address) view returns (bytes32 teamId, uint64 mintedAt, bool exists)`
- `tokenIdOf(address) view returns (uint256)`
- `teamOf(address) view returns (bytes32)`
- `teamFanCount(bytes32) view returns (uint256)`

Required Hook ABI function:

- `getUserContribution(address,bytes32) view returns (uint256 swapPoints, uint256 lpPoints, uint256 totalPoints, uint64 lastActionAt)`

If the exact generated getter signature differs, adapt to the installed contract and document the final ABI in the report.

### 2. Team constants

Create:

```text
frontend/lib/teams.ts
```

Export four teams with:

- symbol: `BRA | ARG | FRA | GER`
- name
- flag emoji
- `teamId` from committed deployment data, not recomputed ad hoc
- token address
- pool ID

Do not introduce licensed tournament/FIFA branding.

### 3. Faucet panel

Create:

```text
frontend/components/FaucetPanel.tsx
```

Requirements:

- Shows xUSD plus BRA/ARG/FRA/GER.
- For each token, shows:
  - symbol/name
  - current connected-wallet balance
  - faucet amount
  - cooldown status based on `lastFaucetAt + FAUCET_COOLDOWN`
- Claim button calls `faucetMint(connectedAddress)` via `useWriteContract`.
- Use `useWaitForTransactionReceipt` to show pending/success/failure and refetch reads. Avoid `setTimeout`.
- Disable claim button when:
  - no wallet connected
  - wrong network
  - transaction pending
  - cooldown active
- For cooldown display, browser `Date.now()/1000` is acceptable.
- Display compact per-token transaction status. Full toast system is optional; inline status is enough.

### 4. Team selector

Create:

```text
frontend/components/TeamSelector.tsx
```

Requirements:

- Four selectable cards/buttons for BRA, ARG, FRA, GER.
- Shows flag emoji, symbol, and name.
- Single-select only.
- Accessible enough for demo: real buttons, selected state visible.

### 5. Passport card

Create:

```text
frontend/components/PassportCard.tsx
```

Requirements:

- If no wallet connected: show `Connect wallet to mint a Team Passport`.
- If connected but wrong network: show `Switch to X Layer testnet to mint`.
- If wallet has no passport:
  - show `TeamSelector`
  - show `Mint Passport` button
  - call `mintPassport(teamId)` via `useWriteContract`
  - wait for receipt and refetch passport reads
- If wallet has a passport:
  - show selected team symbol/name/flag
  - show token ID from `tokenIdOf(address)`
  - show `Soulbound` label
  - read and display `getUserContribution(address, teamId)` from the Hook
  - zero contribution before activity is acceptable
- Do not expose transfer UI.

### 6. Integrate into page

Update `frontend/app/page.tsx`:

- Replace the P06-02 placeholder with live `FaucetPanel` and `PassportCard`.
- Keep P06-03/P06-04 placeholders.
- Preserve existing wallet/network/deployment status shell.
