# Directive — D6 for P03-01

## Goal

Implement `XCupLeagueRegistry.sol`, the shared metadata and match-state registry that maps teams to pools and pools back to teams. This phase should compile the standalone registry only; Hook integration and registry tests are deliberately separate later phases.

## Scope (In)

- Add `contracts/src/XCupLeagueRegistry.sol` with SPDX `MIT` and `pragma solidity 0.8.26;`.
- Imports must be exactly the dependencies needed for the phase:
  - `import {Ownable} from "@openzeppelin/contracts/access/Ownable.sol";`
  - `import {PoolId} from "@uniswap/v4-core/src/types/PoolId.sol";`
  - `import {Currency} from "@uniswap/v4-core/src/types/Currency.sol";`
- Contract name: `XCupLeagueRegistry is Ownable`.
- Include the enum in this exact order:
  ```solidity
  enum MatchState { PRE_MATCH, LIVE_NORMAL, GOAL_SHOCK, RED_CARD, PENALTY, FINAL_WHISTLE }
  ```
- Include PRD-shaped data structs sufficient for future Hook reads:
  - `Team` with fields for at least `string name`, `string symbol`, `address token`, `string metadataURI`, and `bool exists`.
  - `PoolConfig` with fields for at least `bytes32 teamId`, `Currency fanToken`, `Currency quoteToken`, and `bool exists`.
  - `MatchStateData` with fields for at least `MatchState state`, `string reason`, `uint64 updatedAt`, and `bool exists`.
- Add storage:
  - `mapping(bytes32 => Team) public teams;`
  - `mapping(PoolId => PoolConfig) public poolConfig;`
  - `mapping(bytes32 => MatchStateData) public matchStateOfTeam;`
  - `bytes32[] public teamIds;`
  - `address public controller;`
- Constructor signature: `constructor(address owner_) Ownable(owner_)`. In the constructor body set `controller = msg.sender` for MVP compatibility with the phase file, but ensure the owner can also act through `onlyController`.
- Add modifier `onlyController()` that allows `msg.sender == controller || msg.sender == owner()` and otherwise reverts with `NotController(address caller)` (or equivalent custom error carrying the caller).
- Implement these functions:
  - `registerTeam(bytes32 teamId, string calldata name, string calldata symbol, address token, string calldata metadataURI) external onlyOwner`
  - `registerPool(PoolId poolId, bytes32 teamId, Currency fanToken, Currency quoteToken) external onlyOwner`
  - `setMatchState(bytes32 teamId, MatchState state, string calldata reason) external onlyController`
  - `setController(address newController) external onlyOwner`
  - `getTeamIds() external view returns (bytes32[] memory)`
  - `getTeamByPool(PoolId poolId) external view returns (bytes32 teamId)`
  - `getMatchStateByPool(PoolId poolId) external view returns (MatchState)`
  - `isRegisteredPool(PoolId poolId) external view returns (bool)`
- Events:
  - `TeamRegistered(bytes32 indexed teamId, string name, string symbol, address indexed token, string metadataURI)`
  - `PoolRegistered(PoolId indexed poolId, bytes32 indexed teamId, Currency fanToken, Currency quoteToken)`
  - `MatchStateUpdated(bytes32 indexed teamId, MatchState state, string reason, uint64 updatedAt)`
  - `ControllerUpdated(address indexed oldController, address indexed newController)`
- Custom errors for every revert path. At minimum include and use: `InvalidTeamId`, `InvalidToken`, `InvalidController`, `TeamAlreadyRegistered`, `TeamNotRegistered`, `PoolAlreadyRegistered`, `PoolNotRegistered`, `NotController`.
- Validation rules:
  - `teamId != bytes32(0)` for team registration, pool registration, and match-state updates.
  - `token != address(0)` in `registerTeam`.
  - Team must exist before `registerPool` or `setMatchState`.
  - Pool cannot be re-registered.
  - For MVP, reject `Currency.unwrap(fanToken) == address(0)` and `Currency.unwrap(quoteToken) == address(0)` in `registerPool`.
  - `setController` rejects `address(0)`.
- When a team is registered, append its ID to `teamIds` exactly once and initialize `matchStateOfTeam[teamId]` to `PRE_MATCH` with `exists = true`.
- Run verification from inside `contracts/` and paste verbatim results into the report:
  - `forge build`
  - `forge fmt --check`
  - `forge test -vvv`
  - `git diff -- contracts/src/XCupLeagueRegistry.sol`
  - `wc -l src/XCupLeagueRegistry.sol`

## Constraints

- Solidity 0.8.26 only. Do not bump compiler or enable `via_ir`.
- Use OpenZeppelin v5 `Ownable` constructor style, matching earlier contracts.
- Use Uniswap v4 `PoolId` and `Currency` UDVTs directly. Do not replace them with raw `bytes32`/`address` in storage or public function signatures.
- Keep the implementation simple and readable for the hackathon. Do not introduce inheritance hierarchies, libraries, role-manager dependencies, or storage packing cleverness.
- If `Currency.unwrap(...)` is unavailable or the installed v4-core API differs, stop and write a `BLOCKED` report with the exact compiler error rather than changing the public shape away from `Currency`.
- Commit convention: implementation commit `[P03-01] add league registry`; final report/state commit `[P03-01] report + state update`.
