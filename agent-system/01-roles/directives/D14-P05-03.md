# Directive — D14 for P05-03

## Context

P05-02 is accepted. The repo now has scripts for token deployment, core deployment, pool creation, and seed liquidity. Local anvil E2E passed through `DeployTokens -> DeployCore -> CreatePools -> SeedLiquidity`, all four pools registered true, and one post-seed BRA swap succeeded through the script helper.

This phase is the X Layer testnet deployment phase. It is time-sensitive and demo-critical.

## Goal

Deploy the full X Cup Liquidity League stack to X Layer testnet (`chainId = 1952`), commit the testnet deployment manifests, perform best-effort explorer verification and smoke checks, and update the README with deployed addresses and explorer links.

## Scope (In)

### 1. Pre-flight environment and chain checks

From `contracts/`:

- Confirm `.env` exists locally and is not committed.
- Confirm the deployer has a funded X Layer testnet OKB balance before broadcasting:
  ```bash
  cast chain-id --rpc-url xlayer_testnet
  cast balance <deployer-address> --rpc-url xlayer_testnet
  ```
- `cast chain-id --rpc-url xlayer_testnet` must return `1952`.
- If deployer balance is insufficient for deployment gas, stop and produce a `BLOCKED` report requesting testnet OKB. Do not continue with partial testnet broadcasts.

### 2. PoolManager decision

Before broadcasting `DeployCore.s.sol`, determine whether there is a canonical/usable Uniswap v4 `PoolManager` address on X Layer testnet.

- If a confirmed canonical PoolManager address is available, set `POOL_MANAGER_ADDRESS=<address>` in local `.env` and use it.
- If no confirmed canonical address is available, use the project-owned fallback path:
  - Update `DeployCore.s.sol` only as much as needed to allow a deliberate deploy-owned-PoolManager mode on X Layer testnet.
  - This must be explicit, not accidental. Use an env flag such as:
    ```bash
    DEPLOY_OWN_POOL_MANAGER=true
    ```
  - Never silently deploy a PoolManager on non-local chains just because `POOL_MANAGER_ADDRESS` is unset.
  - Record the decision in the report and README limitations/future work.

Rationale: hackathon completion and demonstrability beats waiting for a chain-level canonical v4 deployment. A project-owned PoolManager on X Layer testnet is acceptable for MVP if clearly disclosed.

### 3. Execute X Layer testnet deploy scripts

Run in order from `contracts/`:

```bash
forge script script/DeployTokens.s.sol --rpc-url xlayer_testnet --private-key $DEPLOYER_PRIVATE_KEY --broadcast
forge script script/DeployCore.s.sol --rpc-url xlayer_testnet --private-key $DEPLOYER_PRIVATE_KEY --broadcast
forge script script/CreatePools.s.sol --rpc-url xlayer_testnet --private-key $DEPLOYER_PRIVATE_KEY --broadcast
forge script script/SeedLiquidity.s.sol --rpc-url xlayer_testnet --private-key $DEPLOYER_PRIVATE_KEY --broadcast
```

If you changed `DeployCore.s.sol` for explicit deploy-owned-PoolManager mode, include that change in this phase and re-run:

```bash
forge fmt --check
forge build
forge test -vvv
```

Commit the X Layer testnet deployment JSON files. Do not commit any local anvil `deployments/31337/` artifacts.

### 5. Smoke checks

After deployment, run and record at least:

- `cast chain-id --rpc-url xlayer_testnet` returns `1952`.
- `cast code <each major contract> --rpc-url xlayer_testnet` returns non-empty code for:
  - xUSD
  - at least one fan token
  - TeamPassport
  - XCupLeagueRegistry
  - XCupLiquidityLeagueHook
  - PoolManager used by the deployment
  - V4PoolActionHelper / seeder helper if deployed by `SeedLiquidity`
- `registry.getTeamIds()` returns four entries.
- `registry.isRegisteredPool(poolId)` returns true for all four pools.
- `hook.getTeamScore(<BRA_TEAM_ID>)` returns a readable zero-or-nonzero struct.
- At least one testnet swap through `V4PoolActionHelper` succeeds if enough seeded liquidity and token allowance exists. If this is not practical after deployment, document why; do not block if pool registration and seed liquidity succeeded.

### 6. Best-effort verification

Attempt explorer verification for the main contracts if `OKX_EXPLORER_API_KEY` / verifier endpoint works:

- `DemoQuoteToken`
- one or all `DemoFanToken` instances
- `TeamPassport`
- `XCupLeagueRegistry`
- `XCupLiquidityLeagueHook`
- `V4PoolActionHelper` if deployed and useful for demo interaction
- project-owned `PoolManager` only if deployed by this project and verification is practical

If OKX explorer verification fails due to API format, endpoint incompatibility, constructor args, or unsupported Foundry verifier behavior, document the exact failure in the report and continue. Verification is best-effort, not blocking.
