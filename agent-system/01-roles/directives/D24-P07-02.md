# Directive — D24 for P07-02

## Goal

Produce the submission media package: a 1–3 minute demo-video script/shot plan, X post copy, and either live published URLs or a precise BLOCKED report explaining which human credentials/actions are missing.

This phase is allowed to be partially human-dependent. Do not fake links. Do not claim publishing happened unless it actually happened.

## Scope (In)

### 1. Frontend hosting check

If the Executor environment has access to a hosting path such as Vercel/Netlify/Cloudflare Pages credentials, deploy the frontend and capture the public URL.

If no hosting credentials are available:

- Do not block the whole phase.
- Record `Frontend URL: local-only for now`.
- Keep README/DEMO local URL accurate.
- Recommend user record from `http://127.0.0.1:3000`.

Do not commit secrets or platform tokens.

### 2. Create demo video package

Create:

```text
submission/video-script.md
```

It must include:

- Target duration: 1–3 minutes.
- Suggested format: 1080p screen recording.
- Exact shot list with timestamps.
- Voice-over script or caption text.
- Demo actions in order:
  1. Repo/README proof.
  2. Contract proof panel with X Layer addresses.
  3. Wallet connect on X Layer testnet.
  4. Faucet token claim.
  5. TeamPassport mint.
  6. Leaderboard before/after swap.
  7. Swap panel action.
  8. Liquidity support panel action.
  9. Admin `?admin=1` match-state update.
  10. Event log showing hook/registry events.
- Fallback instructions if swap/liquidity browser transaction is slow:
  - show already-deployed smoke tx from P05-03
  - show live leaderboard/event log panels
  - state clearly that full frontend write paths are implemented

Also create:

```text
submission/recording-checklist.md
```

Checklist must include:

- use a fresh wallet or one with available faucet cooldown
- fund wallet with testnet OKB
- confirm X Layer testnet chain ID 1952
- run `cd frontend && pnpm dev --hostname 127.0.0.1 --port 3000`
- open normal URL and admin URL
- test wallet connect
- rehearse faucet/passport/swap/liquidity/admin update
- verify no private keys or `.env` visible on screen

### 3. X post package

Create:

```text
submission/x-post.md
```

It must include:

- A primary post under normal X character limits.
- A slightly longer fallback post if user wants a thread.
- Required tag: `@XLayerOfficial` based on `hackathon-details.md`.
- Include repo URL.
- Include demo video URL placeholder if not uploaded yet.
- Include frontend URL placeholder or local-demo note if not hosted.
- Include deployed hook address.
- Include registry address.
- Include 1–2 pool IDs, not fake pool explorer URLs.
- Use a clear hackathon tag. If no canonical hashtag is verified from repo docs, use `#XCupHackathon` and note it as repo-plan default.

```text
SUBMISSION.md
```

Include fields:

- Repo URL
- Frontend URL: `TBD` or actual URL
- Demo video URL: `TBD` or actual URL
- X post URL: `TBD` or actual URL
- X account handle: `TBD` unless known
- Hook address

- Notes for final Google Form

If a video or X post is actually published, update these URLs and README submission links. If not, keep them as TBD.

### 5. Report/state

Create:

```text
agent-system/04-summaries/reports/P07-02.md
```

The report must be honest and classify status as:

- `DONE` only if demo video URL and X post URL both exist; or
- `BLOCKED` if credentials/human recording/upload/posting are still required; or
- `PARTIAL` if assets are prepared but one URL is missing.

Given likely executor limitations, `PARTIAL` is acceptable if the video script, checklist, X post copy, and SUBMISSION.md placeholders are complete.

Update:

- `agent-system/04-summaries/execution-log.md`
- `agent-system/03-state/state-counter.md`
- `agent-system/03-state/phase-status.md`

If URLs are missing, keep P07-02 as `PARTIAL` or `BLOCKED` and state exact human action needed. If fully done, advance to P07-03.
