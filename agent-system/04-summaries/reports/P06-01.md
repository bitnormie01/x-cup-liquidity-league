# P06-01 Report - Next.js + wallet + network

## Summary

Bootstrapped the frontend under `frontend/` with Next.js App Router, TypeScript strict mode, Tailwind, wagmi, viem, and a lightweight injected-wallet connector. The shell displays the X Cup Liquidity League title/subtitle, wallet connect/disconnect controls, X Layer testnet network badge, P05-03 deployment status, four pool IDs, and the three placeholder panels reserved for P06-02 through P06-04.

The deployment data is exposed from `frontend/lib/deployments.ts` as typed constants using the committed P05-03 X Layer testnet manifests as source of truth.

## Implementation Notes

- Used wagmi + viem with the injected connector only; RainbowKit was intentionally skipped to avoid extra UI/dependency weight.
- Imported `injected` from `@wagmi/core` directly to avoid bundling warnings from the broader connector barrel.
- Added X Layer testnet chain config with chain ID `1952`, OKB native currency, `https://testrpc.xlayer.tech/terigon`, and OKX explorer URL.
- Added `frontend/lib/deployments.ts` typed constants for token addresses, core addresses, pool IDs, team IDs, and `poolManagerMode`.
- Displayed the project-owned PoolManager disclosure in the deployment status panel.
- Added `pnpm-workspace.yaml` build approvals required by pnpm 11 for native optional dependencies.
- Added `frontend/.next` to `.gitignore` because validation used an ignored `/tmp` symlink for the build cache on this space-constrained host.

## Risks / Caveats

- Wallet behavior was validated at build/runtime shell level only; MetaMask interaction requires a real browser wallet and remains for manual demo testing.
- The frontend currently performs no live contract reads or writes, per D16 scope.
- Deployment data is static and must be updated manually if P05-03 manifests change.
- Local validation needed `/tmp` storage because `/home` had limited free space.
